## Current status: Python dataset pipeline

The repository's first code is the EIA weekly analyst dataset pipeline
(introduced by the `feat/dataset-pipeline` PR):

- **Stack:** plain Python 3 (developed and tested on 3.13); no framework,
  no Dockerfile, no package manager beyond `pip`.
- **Layout:** `scripts/build_dataset.py` (+ `scripts/requirements.txt`) —
  downloads six weekly EIA series from public spreadsheets, joins on the
  Friday `week_ending`, converts thousand → million barrels, computes the
  5-year seasonal baseline, writes `data/full.csv`, `data/notes_input.csv`,
  `data/answers.csv` (13 rows, 2026-06-19 → 2026-09-11).
- `skills/note-writer.md`, `skills/scorer.md` — analyst and scorer prompts,
  tuned (note-writer v3, scorer v2); `docs/skill-tuning-log.md` records the
  one-change-at-a-time tuning and validation evidence.
- `docs/data-sources.md` — pinned sources, units, data wrinkles.
- `scripts/validate_note.py`, `scripts/verdict_rule.py` — mechanical checks
  the skills reference (note shape/banned phrases/one-row rule; scorer ±1%
  band boundary cases). Keep both ruff-clean; their behavior is pinned by
  `tests/test_skill_tooling.py`.
- `tests/` — pytest suite (unit conversion, baseline math, join integrity,
  split-guard).
- CI: `.github/workflows/ci.yml` runs `ruff check` + `pytest` on PRs and
  pushes to `main`.

## How to work here

- **Data pipeline commands:**
  `pip install -r scripts/requirements.txt` ·
  `python scripts/build_dataset.py` (needs network access to `eia.gov`) ·
  `pytest -q` · `ruff check scripts tests`.
- Tests run offline against the committed CSVs; only the build script needs
  network.
- **Do not merge `data/notes_input.csv` with `data/answers.csv`** — the
  physical notes/answers split is load-bearing (see `docs/data-sources.md`),
  and `tests/test_split_guard.py` enforces it.
- A full repo contract (codebase map, snapshot info) arrives with the next
  setup run as the application grows.
